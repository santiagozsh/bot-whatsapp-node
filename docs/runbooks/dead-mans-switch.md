# Runbook: Dead Man's Switch & Incident Remediation

> Standard Operating Procedure (SOP) for responding to alerts generated by the Luxury Gotti WhatsApp accounting bot observability stack.

---

## 1. Overview & Severity Tiers

The observability pipeline sends automated Telegram alerts when system health degrades.

| Severity | Alert Rule | Trigger Condition | Impact | Target SLA |
| :--- | :--- | :--- | :--- | :--- |
| **P1 — Critical** | `BotHostUnreachable-DeadMansSwitch` | `absent_over_time(up[5m]) == 1` | Host machine is offline or internet disconnected. Zero telemetry reaching Grafana Cloud. | < 15 minutes |
| **P1 — Critical** | `BotWhatsAppDisconnected` | `bot_whatsapp_connection_state < 1` for > 5m | WhatsApp WebSocket is disconnected or session has been revoked. Receipts are not being recorded in Google Sheets. | < 10 minutes |
| **P2 — Warning** | `BotSheetsWriteErrors` | `rate(bot_sheets_operations_total{status="error"}[5m]) > 0` | Google Sheets API rate limits or network timeout during spreadsheet updates. | < 1 hour |

---

## 2. Remediation Procedures

### Incident A: `BotHostUnreachable-DeadMansSwitch` (Host Down)

1. **Verify SSH / Machine Status:**
   - Attempt to connect to the host machine via SSH.
   - If unreachable, check power and internet connectivity on the host.
2. **Inspect Docker Containers:**
   ```bash
   docker ps
   ```
3. **Restart the Entire Stack:**
   ```bash
   docker compose up -d
   ```
4. **Verify Alloy Scraper Status:**
   ```bash
   docker logs grafana-alloy --tail 50
   ```
   Ensure Alloy reports `{^_^} Alloy is running` and is forwarding metrics.

---

### Incident B: `BotWhatsAppDisconnected` (WhatsApp Lost or Session Revoked)

1. **Check Live Bot Logs via Docker or Grafana Loki:**
   - In Grafana Loki, query:
     ```logql
     {job="whatsapp-bot"} |= "WHATSAPP"
     ```
   - Or locally:
     ```bash
     docker logs node-bot-dev --tail 100
     ```
2. **Scenario B.1: Temporary Network Disconnection (Reconnecting automatically)**
   - If the bot logs show `Retrying connection in Xs...`, wait up to 2 minutes for exponential backoff to recover.
3. **Scenario B.2: Session Revoked / QR Code Scan Required**
   - If the metric `bot_whatsapp_connection_state == -1` or logs indicate `Session revoked`:
   - View the QR code in the terminal logs:
     ```bash
     docker logs -f node-bot-dev
     ```
   - Open WhatsApp on the linked phone -> **Linked Devices** -> Scan the QR code displayed in the logs.
   - Once connected, verify the log: `[WHATSAPP] ✅ Connected and listening for group messages`.

---

### Incident C: `BotSheetsWriteErrors` (Google Sheets Failures)

1. **Query Google Sheets Logs in Loki:**
   ```logql
   {job="whatsapp-bot"} |= "SHEETS"
   ```
2. **Verify Google Service Account Credentials:**
   - Confirm `google-keys.json` is present and valid.
   - Verify that the target Google Spreadsheet ID in `.env` (`GOOGLE_SHEETS_ID`) has granted `Editor` permissions to the service account email.
3. **Verify API Quotas:**
   - Check Google Cloud Console for Sheets API rate limits (100 requests per 100 seconds per user).

---

## 3. Failure Drill (Verification Procedure)

To execute a planned recovery drill:
1. Stop the bot container: `docker stop node-bot-dev`.
2. Confirm that Telegram receives the `[FIRING] BotWhatsAppDisconnected` notification within 5 minutes.
3. Start the bot container: `docker start node-bot-dev`.
4. Confirm that Telegram receives the `[RESOLVED] BotWhatsAppDisconnected` recovery notification.
